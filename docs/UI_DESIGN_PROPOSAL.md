## 0. 结论

三处改动，方向是「**层次清楚、字大 comfortable、按钮有主次**」：

1. **字号整体 +2px** —— 解决「菜单栏和辅助文字都太小」
2. **浅色主题的弹框改成比窗口亮** —— 解决「在浅色窗口上挖了个洞」
3. **深色主题层次拉开** —— 解决「大片近黑、什么都糊在一起」

**所有颜色改动都过了调色板的实测契约**（`border ≥2.34`、`accent_soft ≥1.12`、
强调色上文字 `≥4.5`、文字四档在六个底色上 `≥4.5`、底色之间 `ΔE ≥3.0`）。

**第二轮补的**（2026-10-20 晚）：

4. **字重加厚** —— 见 §1.5
5. **欢迎页「快速连接」卡片** —— 见 §1.6
6. **标签页右键菜单** —— 关闭当前 / 关闭其他 / 关闭右侧

## 1. 改了什么

### 1.1 字号（QSS 表整体 +2px）

**为什么**：QSS 里写的是 `font-size: 13px`，经 `_font_size_to_pt` 换算成
**9.75pt = 13px**；而应用字体是 `ui_font(11)` = **11pt = 14.67px**。
**QSS 把所有带样式的文字压小了 1.67px** —— 菜单栏、辅助文字、
分组标题全是小字。

| 用途 | 原 | 新 | pt |
|---|---|---|---|
| 欢迎页大标题 `welcomeTitle` | 28px | **32px** | 24pt |
| 终端主机名 `host` | 20px | **23px** | 17.25pt |
| 品牌标题 / 欢迎副标题 | 16px | **18px** | 13.5pt |
| **会话名 / 传输标题** | 13px | **15px** | 11.25pt |
| 分区标题 / 主机 / 分组名 / 提示 | 12px | **14px** | 10.5pt |
| 分组计数 | 11px | **13px** | 9.75pt |

> 12px 原来是**用得最多**的（11 处），却是全套里最小的正文字号。

### 1.2 控件尺寸

| 项 | 原 | 新 |
|---|---|---|
| `CONTROL_H`（按钮/输入框基准高） | 34 | **36** |
| 主按钮 `role="cta"` | 36 | **40** |
| 强调色色块 `role="accentSwatch"` | 30 | **32** |

`CONTROL_H` 是**单一来源**（QSS 表里 10 处引用），改一处全局生效。
`min-height` 而不是写死 `height` —— 高度要跟着界面字号缩放。

### 1.5 字重加厚（第二轮）

**问题**：字号提上去了，但还是「不够厚重」。

**根因**：`ui_font()` 从没设过字重，用的是 QFont 的默认 **Normal(400)**。
在 Windows 的 Segoe UI Variable / 微软雅黑 上，11pt 的 Normal 偏细 ——
整屏看下去「发飘」。QSS 里只给 7 个 role 设了 `font-weight: 600`，
**菜单栏、按钮、输入框、次要文字全是 Normal**。

**修法**：

| | 原 | 新 |
|---|---|---|
| 界面字体基线 | Normal(400) | **Medium(500)** |
| `welcomeTitle` / `brandTitle` / `host` | 600 | **700** |
| 其余 4 个 role（section / sessionName / groupName / transferTitle） | 600 | 600（不变）|

**别一刀切成 Bold(700)。** 字重是分层的 —— 正文就该比标题轻。
基线抬到 500，标题再高一档，层次才清楚。

> 在只认 Regular/Bold 的字体上（非可变的 微软雅黑），600 与 700 渲染成同一个
> Bold，提了也没有副作用；在可变字体上（Segoe UI Variable）才看得出差别。

### 1.6 欢迎页「快速连接」卡片（第二轮）

**问题**：欢迎页原来只有中间那一坨，左边一大片空白。

加一张卡片列出已保存的会话，点一下就连。

- **不用「最近」这个词** —— `SavedSession` 里没有「上次使用时间」字段，
  按什么排序都是假的。叫「快速连接」，列的就是已保存的会话。
- 最多列 5 条（`QUICK_MAX`）—— 多了就成列表了，欢迎页要的是一眼能看完的入口
- 卡片是 `QFrame` 而不是 `QWidget` —— QSS 规则是 `QFrame[role="card"]`，
  用 QWidget 规则不匹配、背景画不出来
- 与侧栏同步：`_reload_session_list()` 里一并刷新，避免「刚删掉的会话还在卡片上」

### 1.7 标签页右键菜单（第二轮）

右键标签 → **关闭当前 / 关闭其他 / 关闭右侧**。

- 走**与关闭按钮同一条路**（`tabCloseRequested`）—— 所以欢迎页那个不可关闭的
  标签在菜单里自动是灰的
- 「关闭其他」「关闭右侧」**从大到小关** —— 关掉一个会让后面的下标全部前移
- 右键「按下与释放」必须在**同一个标签**上，否则会在别的标签上弹菜单

---

`palette.py` 里的颜色**带实测契约**（注释里记着）：

- `border` 对 `bg_surface` / `bg_rail` / `bg_base` 三档都 **≥2.34**
  （「肉眼明显可见」的下界；上界 2.6 从来没成立过，**不立**）
- `accent_soft` 对其底色 **≥1.12**
- 强调色三态与实心档上的文字 **≥4.5**（AA）
- 强调色饱和度 ≈ **0.880**（深色专属；浅色那条是 0.752，另一番取舍）
- 文字四档在六个底色上都 **≥4.5**
- 底色之间 **ΔE ≥3.0**（同一族里要"一眼分得开"）

手调必破其中一条，而且**破了通常不报错** —— 只是某个控件在某个底色上看不见。
所以这次用 `tests/_design_check.py` 把候选值过一遍契约，全过了才落地。

**顺带查出浅色主题现状就有一处违约**：`border~bg_rail` 实测 **2.146 < 2.34**。
根因是 `bg_surface` 是纯白 `#FFFFFF` —— 只要有纯白底，边框就必须够深，
这正是那条重边框的**来源**。抬了 `bg_base`/`bg_rail` 之后，边框才降得下来。

## 3. 层次方向（最重要的一处）

**两个主题原本方向相反**：

| | 窗口底 | 弹框底 | 读作 |
|---|---|---|---|
| 深色（原来） | `#0d0f14` | `#1e2431` | 弹框更亮 = **浮起** ✓ |
| 浅色（原来） | `#F6F5F2` | `#E4E3DE` | 弹框更暗 = **挖了个洞** ✗ |

现在统一成「**弹框比窗口亮**」：

```
深色：窗口 #101319  →  弹框 #1f2430  →  表面/输入 #181b23 / #14171e
浅色：窗口 #F2F1EE  →  弹框 #FCFBF9  →  表面/输入 #FFFFFF / #FFFFFF
```

## 5. 顺手修掉的一个真机崩溃

真机启动时报的：

```
Exception in thread Thread-137 (worker):
  File ".../sshclient/ui/monitor_panel.py", line 522, in worker
    QtCore.QMetaObject.invokeMethod(
RuntimeError: wrapped C/C++ object of type MonitorPanel has been deleted
```

**根因**：监控面板是 `SessionTab` 的子控件，关标签时 `w.deleteLater()` 连带
把它销毁；而 worker 正卡在 `conn.exec(PROBE_CMD, timeout=10)` 里最多 10 秒，
醒来再往那个已销毁的对象上 `invokeMethod` 就炸了。

**不是「偶尔」** —— 关标签是常规操作，轮询间隔 2 秒、exec 超时 10 秒，
关得早了就必撞。

**修法**（`sshclient/ui/thread_post.py`）：投之前先 `sip.isdeleted(obj)`，
再套一层 `try/except RuntimeError`（挡住「查完之后、投递之前」那段窗口）。
同类点还有三处，一起改了：`tunnel_panel.py` 两处、`main_window.py` 两处。

**还有一个更隐蔽的**：主窗口关闭时，正在等「要不要信任这台主机」的连接
worker 卡在 `ask.event.wait(timeout=120)` —— 那个 wait 只有主线程跑那个槽
才会被 set。主窗口一关，槽永远不跑，worker **干等 120 秒**。
修法：`closeEvent` 里把 pending 的 request 全部 `accept=False; event.set()`。

## 6. 一个必须记着的教训：分隔线被删掉了，色差就是唯一的分隔

`palette.py` / `qss.py` 里，侧栏的 `border-right`、状态栏与菜单栏的
`border-top` 都是**刻意删掉**的，注释写着：

> 那条线跟 `bg_rail` 那个色差是同一件事，删掉之后那条线就跟色差完全同量级了，
> **全靠颜色区分**。

所以改底色时**必须同时验色差还在不在**。第一轮改色就踩了：

| 关系 | 改前 ΔE | 改后 ΔE | |
|---|---|---|---|
| 浅色 侧栏↔主区 | 26.57 | **14.46** | 腰斩 |
| 浅色 弹框↔主区 | 32.37 | **17.92** | 腰斩 |
| 深色 弹框↔按钮 | 9.90 | **4.69** | 腰斩 |

量法见 `tests/_design_separate.py`（改动前后逐对比）。**这个量应该成为
改配色的固定动作** —— 不然「删了线、色差又不够」的回归会静悄悄发生。
